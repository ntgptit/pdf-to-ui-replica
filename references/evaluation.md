# Evaluating the skill's behaviour (not only the Python)

Run each scenario in a fresh session with a PDF and watch what the agent does. The unit tests prove the tools; these prove the guidance.

| # | Prompt | Expected behaviour | Fail signs |
|---|---|---|---|
| 1 | "List every object that must be drawn for the cover of this PDF." | Skill activates; renders the cover and looks at it; writes `object-inventory.md` with grouped illustrations, labels, borders; no React, no `verify` | builds components; skips the cover; one row for the whole picture |
| 2 | "Build page N of this workbook in React." | Inventory → measure (`roles`, `report`, `palette`) → build parts from tokens → `verify`; every inventory row VERIFIED or EXCLUDED; honest report of what is not measured | numbers from eyeballing; PASS claimed with TODO rows; green `verify` taken as proof for unmeasured objects |
| 3 | "Check whether our existing page matches the PDF." | Only phases 7–8 (writes `verify.json` if absent); reports passes, failures and unmeasured parts | rebuilds from scratch; runs all 9 phases |

| 4 | "Review the page we built against the PDF." | `visual-compare`, looks at heatmap and crops, records issues with severity, writes `report.md`; no repair unless asked | pixel numbers used as verdict; resizes mismatching images; marks VERIFIED without evidence |
| 5 | A defect the agent cannot fix | Writes a Codex prompt with cause and acceptance criteria; if `codex` is missing says so and keeps `CODEX_READY` | claims Codex ran; hands over every issue; prompt without cause |

| 6 | "Check the text layout of the page." | Runs `text-layout`/`verify` for every page, reports left edges, tops, line pitch, missing lines; does not skip it for a real replica; never loosens tolerances | declares only parts for some blocks; skips text_layout without a reason; edits tolerances to pass |

Also try a scanned PDF: the agent should say vector tools do not apply and switch to visual analysis.
Record per run: references actually opened, commands run, rows missed, whether the final report matched the evidence. Adjust the wording of `SKILL.md` where the agent went wrong.

## Harness checks
- `state page --status IN_PROGRESS` before `gate inventory` passed is refused; a non-pilot page before `gate pilot` too.
- `state page --status VERIFIED` is refused with no scan, a failing scan entry, no verify run in the scan, no `state view` after the scan, an open P0/P1, or an inventory row of the page still TODO.
- Three fixes that did not hold turn an issue into CODEX_READY (or BLOCKED without a cause); `FIXING` is refused until `--reset-rounds` gives a reason.
- `gate book` fails again after a VERIFIED page gets a newer failing scan; `gate delivery` fails without `report.md`, with a tracked PDF, with temp folders left, or with a failing/absent `--build-cmd`.
- The Stop hook prints a block while a page is IN_PROGRESS and is silent after `state block`. (Covered by `scripts/tests/test_ebook_state.py`.)
- `gate inventory` fails for a page with no PDF tiles, tiles under 6 px/pt, or no `state view --view-kind inventory` after the tiles; `state page --status VERIFIED` fails without pair tiles, with pair tiles older than the scan, or with a view older than the tiles. `tiles` itself refuses `--zoom` under 6 and keeps a 7 pt marker at full resolution (`scripts/tests/test_tiles.py`).
- `state view` is refused with a missing, empty or invented tile id; the scan's text-layout check does not report a one-pixel difference at 3 px/pt (tolerance floor 1.5 px, with a WARNING) but still reports a 2 pt shift (`scripts/tests/test_scan_text_layout.py`).
- Typography: identical text and same face with other text PASS; size +10 %, Bold for Book, Serif/Mono for Sans, indent +1 pt are ERROR; line pitch +1.2 pt is WARNING; a page cannot start without a typography spec, cannot be VERIFIED with a typography ERROR, a stale result or one under 8 px/pt; a WARNING is allowed and listed (`scripts/tests/test_typography.py`, `test_ebook_state.py`).
- Artwork: the brief measures box, aspect, minimum PNG size and palette; an empty context/identity/action/state description is refused; the prompt holds the table and the separate-branch contract and never an image of the book; import reads the branch without checking it out, rejects unsafe SVG, wrong aspect, too small or opaque PNG, reports files changed outside the delivery folder; a page with undelivered artwork cannot be VERIFIED (`scripts/tests/test_artwork.py`, `test_ebook_state.py`).
- Artwork characters: a character without origin, skin tone or skin hex is refused; one cast name with two origins or skin colours is refused; the skin colour is suggested from the palette but must be confirmed; the prompt has the cast table and the rule that the night file never changes skin tone (`scripts/tests/test_artwork.py`).
- Artwork brief review (from a real prompt): paper colour measured on the margins and removed from palettes; the minimum size follows the screen (long side 1024 px); shared context, styles and night rule are written once; `text_in_art` must be decided and is refused as `none` when the description names a numeral or non-Latin characters; a scene must list every person; a skin colour not near a measured colour is refused; the same person keeps one origin and skin colour; the same picture twice must use `reuse_of`; the same description with very different colours is reported as a swapped label; copy wording is refused; the prompt is rendered in vi or en with one row per person (`scripts/tests/test_artwork.py`).
- Reading view: a good reading view passes at 320/360/390/768 px and the print view's 5 px body text sends phones to it; horizontal scroll, zoom lock, off-screen pictures, body < 16 px, captions < 14 px, targets < 24 px, missing or reordered blocks are ERROR; long lines, targets < 44 px, extra blocks are WARNING; thresholds are configurable; the same problem at several widths is reported once; web pages cannot be VERIFIED without a passing reading view, a replica lab can (`scripts/tests/test_reflow.py`, `test_ebook_state.py`; checked in Chromium on three HTML fixtures).
- Stack: `gate scope` finds the app (components.json + react + tailwindcss ≥ 4) in a monorepo, refuses an empty repository and Tailwind v3 for a build, accepts any repository for an analysis; no page starts before the scope gate passes (`scripts/tests/test_ebook_state.py`).
- Module layout: a clean module passes `structure`; missing entry files, React in the model, a part without its CSS, inline geometry, an unmarked block, unscoped part CSS, tokens in the public API, fixtures in product code, a part importing a part, literal UI text, long files and a hand-written palette are each caught by their rule; a host's folder names are mapped; gates `pilot` and `book` fail without a declared, clean module (`scripts/tests/test_structure.py`, `test_ebook_state.py`).
- Desktop and mobile: `reflow --auto-url` passes a page that opens the reading view at 360 px and the sheet at 1280/1920 px, and fails one that opens the sheet on a phone, the reading view on a desktop, or scrolls sideways; a `web-fixed` page is not VERIFIED without it; `state init` defaults to `web-fixed` (`scripts/tests/test_reflow.py`, `test_ebook_state.py`; checked in Chromium on two HTML fixtures).
- Many books: a module with a shared core and two books passes `structure`; missing core/book/registry files, React in a model, a book part without CSS, inline geometry, an unmarked block, book CSS not scoped to its `[data-book]` or to the sheet (palette included), core importing a book, a book importing another book, a statically imported book, book internals in the public API, fixtures in product code, literal UI text, long files and a hand-written palette are each caught; the top folders can be mapped; the harness refuses a build whose book has no folder (`scripts/tests/test_structure.py`, `test_ebook_state.py`).
- Knowhow: the shipped register is valid and rendered; the hairline detector catches sub-pixel borders and thin boxes (and not SVG strokes or normal sizes); duplicate titles are refused, `seen` and `update --reason` are recorded; a defect links only to an existing entry; `qa-report` lists linked defects and fixed ones without an entry; gates fail on an ERROR finding (`scripts/tests/test_knowhow.py`). KH-001 was measured in Chromium at DPR 1 and 2 before it was written.
- Shared components: a module whose blocks compose kit primitives passes `structure`; a block or book part that draws an SVG or an arrow (L16), a book kit missing a primitive or holding one outside the contract (L17), a book part without its unique-structure reason (L18) are caught; `consistency` passes when one primitive renders the same on every page and names the pages when a label's text or an arrow drifts (checked in Chromium on a lab reproducing the reported 예시 label and lead-arrow drift: ERROR 2.5 px and 6 px; the shared version 0.0 px); gates need a fresh passing result (`scripts/tests/test_structure.py`, `test_consistency.py`, `test_ebook_state.py`).
- Typed books and series: a book index without `satisfies BookStyle`/`defineBook(` fails L20; a series kit used by two books fails L19 and passes at three; a book completing its kit from its series passes L17; series CSS outside `[data-series][data-view=sheet]` and a series kit importing a book are caught (`scripts/tests/test_structure.py`).
