# Folder architecture of the ebook module (React + shadcn/ui + Tailwind v4)

**Shared components are mandatory.** Every pattern a page repeats (the example label, an answer line with its lead arrow or speaker, a rule, a frame, an item number, a table header…) is **one** component, a kit primitive, used by every page; no page or block draws its own. Two copies of a pattern drift: an example label whose text sits lower on one page, an arrow that rides on the answer rule on one page and sits above it on another. Books have different styles, so the *contract* of each primitive is shared and every book implements it once in its own style.

Built for many books from the first one: a shared **core** (contract, blocks, behaviours, views, the reading view) and one **style pack** per book in `books/<id>/` (its kit, tokens, palette). `pdfmeasure structure` checks the layout, `pdfmeasure consistency` checks that each primitive renders the same on every page, and gates `pilot` and `book` refuse a module that fails either.

## 1. Layout
```
<module>/
  index.ts                       public API: EbookPage, block schemas and types, the book ids
  ebook-page.tsx                 loads the book from books/registry.ts (lazy) and renders core BookPage with its kit
  core/                          shared by every book; never imports a book
    contracts.ts                 BookStyle: id, page size and body pt, kit (one component per primitive), rare parts
    kit/
      contract.ts                export const KIT = ['example-label', 'answer-line', 'rule', 'frame', 'item-number', 'table-header', …] as const
                                 and the props of each primitive (the variants a primitive supports: lead 'arrow' | 'speaker' | none…)
      use-kit.ts                 KitContext + useKit(): the current book's kit in sheet view, the reading kit in reading view
      reading/<primitive>/       the reading-view implementation of each primitive (Tailwind scale + shadcn theme tokens, the same for every book)
    blocks/<kind>/               the renderer of each block kind, written ONCE: it composes kit primitives and never draws a label, line, arrow or
                                 frame itself; behaviour hooks next to it (use-<kind>.ts) or in core/behaviours/
    behaviours/                  logic shared by blocks (answers, audio, matching)
    model/                       pure TypeScript: blocks.ts (Zod schemas), ids.ts, scale.ts
    views/                       book-page (data-book, data-view, KitContext), page-view (content order → blocks), reader-view, view switch
  books/
    registry.ts                  { '<id>': () => import('./<id>') } as const; export type BookId = keyof typeof BOOKS
    _series/<series>/kit/<p>/    ONLY from 3 books of one series (rule L19): the primitives they share, CSS under [data-series=<series>]
    <id>/
      index.ts                   default export: `{ id, page, kit: { … } } as const satisfies BookStyle` (or defineBook); imports palette.css, sheet.css
      kit/<primitive>/           the book's print-sheet implementation of EVERY primitive of the contract: <primitive>.tsx + <primitive>.css
      model/tokens.ts            measured numbers in pt (pure TypeScript)
      styles/palette.css         GENERATED by `pdfmeasure palette --selector '[data-book=<id>]'`
      styles/sheet.css           --wb-pt, page box, the book's faces; under [data-book=<id>][data-view=sheet]
      parts/<kind>/              the exception: a block whose sheet STRUCTURE exists only in this book; first line
                                 `// unique-structure: <why no core block + kit fits>`; it still composes the book's kit
      fixtures/                  original sample pages (each rendered with data-page in the lab); never exported
      artwork-map.json           GENERATED by `artwork import`
lab route                        dev only: every fixture page of every book in both views (what `consistency` measures)
```

## 2. How a pattern is built
1. Spot the pattern in the inventory (phase 2A): anything that appears in two places, on one page or across pages, is a primitive.
2. Add it to `core/kit/contract.ts` (name and props, variants included) and implement it in `core/kit/reading/` and in **every** book's `kit/`.
3. Blocks use it through `useKit()`. A difference between two occurrences is a variant prop of the primitive (`lead="arrow"`), never a second component.
4. Every primitive's root carries `data-kit="<name>"` (and `data-kit-variant` when it has one); inner pieces that must line up carry `data-kit-part` (`lead`, `rule`, `text`…). `consistency` compares them across pages.

## 3. Rules (codes of `pdfmeasure structure`)
| Code | Rule | Why |
|---|---|---|
| L1 | required files: root `index.ts`, `ebook-page.tsx`; core `contracts.ts`, `kit/contract.ts`, `model/blocks.ts|ids.ts|scale.ts`, `views/book-page.tsx|page-view.tsx|reader-view.ts`, at least one block; `books/registry.ts`; per book `index.ts`, `model/tokens.ts`, `styles/palette.css`, `styles/sheet.css` | the same entry points everywhere |
| L2 | models are pure TypeScript | testable without UI |
| L3 | kebab-case folders `<name>/<name>.tsx`; book kit and parts also `<name>.css` | one place per primitive and block |
| L4 | inline `style` sets only CSS custom properties | otherwise the reading view and other books cannot override geometry |
| L5 | blocks and parts mark `data-block`; kit components mark `data-kit="<name>"` | reading parity, deep links, consistency measurement |
| L6 | a book's CSS under `[data-book=<id>]`, its sheet rules also under `[data-view=sheet]`; core CSS under a view | books share class names |
| L7 | `index.ts` exports no tokens, kit, parts, fixtures or book internals | measured details stay inside |
| L8 | fixtures only in tests and the lab | sample content never ships |
| L9 | a block, part or primitive imports no sibling (only `shared/`) | composition happens in blocks via the kit, and in the page view |
| L10 | no literal UI text in `aria-label`, `title`, `alt`, `placeholder` | host i18n |
| L11 | files ≤ 300 non-empty lines | one responsibility per file |
| L12 | palettes are generated | measured colours are never typed |
| L13 | core imports no book | books plug in through the contracts |
| L14 | a book imports no other book | independence |
| L15 | lazy registry | each book its own chunk |
| L16 | blocks and book parts draw nothing themselves: no `<svg>`, `<line>`, `<rect>`, `<path>`, no arrow glyph | every drawn pattern is a kit primitive |
| L17 | every primitive of the contract exists in `core/kit/reading/` and in every book's `kit/`; nothing outside the contract | a book cannot keep a private copy of a pattern |
| L18 | a book part starts with `// unique-structure: <reason>` | parts are the justified exception |
| L19 | `books/_series/<series>/kit/` exists only when at least 3 books import it; its CSS is under `[data-series=<series>][data-view=sheet]`; it imports no book and no other series | a shared base before three books is premature abstraction |
| L20 | every `books/<id>/index.ts` checks its definition at compile time: `satisfies BookStyle` or `defineBook(` | a missing primitive or wrong variant fails in the editor, before `structure` runs |

## 4. Consistency (runtime)
```
PYTHONPATH=. python3 -m pdfmeasure consistency --output O --url <lab URL of the book, sheet view> [--view sheet|reading] [--width 1280] [--tolerance 1]
```
Measures every `[data-kit]` instance and compares those of the same primitive and variant: height, font size, text centre, and each `[data-kit-part]` centre and height. A spread above the tolerance is an ERROR naming the pages (e.g. "answer-line (arrow): lead centre y varies by 6.00 px (page 11 … page 9)"). Run it on the sheet view and on the reading view. Gates `pilot` and `book` need a passing result newer than the latest scan.

## 5. Adding a book
1. `books/<new-id>/` with its tokens, palette (`--selector '[data-book=<new-id>]'`), `sheet.css`, and its implementation of every kit primitive.
2. One line in `books/registry.ts`.
3. A block kind the core lacks: schema, behaviour and block go to the core; a pattern the kit lacks goes to the contract and to every kit (the other books implement it too).
4. Its own harness run (`state init`, `state module --path <module> --book <new-id>`), one palette exemption in the host's token guard.

## 6. Typed books and the registry
- Each book's definition is checked by TypeScript: `const style = { … } as const satisfies BookStyle` or `defineBook({ … })` (`const` type parameter). It fails at compile time when a primitive is missing or a variant prop is wrong, and keeps the id literal. Plain `satisfies BookStyle` checks too but widens the id to `string`; never `const style: BookStyle = …` (widens it) and never `as BookStyle` (hides a missing primitive). Verified with the repository's TypeScript 7.0. Rule L20 checks the source; `L17` stays the folder-level check.
- `BookId = keyof typeof BOOKS`: the registry is the single list of books; `EbookPage({ book })` takes a `BookId`, so an unknown id fails at compile time.
- No factory classes or strategy class hierarchies: the registry is the factory (lazy, one chunk per book), the kit object is the strategy, the context injects it. A class layer would add indirection, pull books into one bundle, and hide imports from the structure checks.

## 7. Series kits: only from 3 books (rule L19)
When **three or more books of one series** share most of their style, their common primitives may move to `books/_series/<series>/kit/<primitive>/`; each book keeps only what differs and composes the kit with object spread:
```ts
// books/sejong-4b/index.ts
import { seriesKit } from '../_series/sejong/kit'
const style = { id: 'sejong-4b', series: 'sejong', page, kit: { ...seriesKit, Frame } } as const satisfies BookStyle   // overrides stay in the book
```
- The series kit's CSS is under `[data-series=<series>][data-view=sheet]` (`BookPage` sets `data-series` from `style.series`); each book's own CSS stays under its `[data-book=<id>]`.
- A book may import only its series kit (rule L14 allows `books/_series/<series>/`); a series kit imports no book and no other series.
- Below three books `structure` fails (L19): keep the primitives in each book's kit. When a series drops under three books, move the series kit back into the remaining books.
- Never inheritance (`class SejongKit extends BaseKit`): composition by spread keeps every primitive visible and checkable.

## 8. A host with its own folder names
Map the two top folders (`--map '{"core": "…", "books": "…"}'`); the inside keeps the layout. When the host's own structure checks disagree with this file, the host wins and the difference goes into the map or the report.
